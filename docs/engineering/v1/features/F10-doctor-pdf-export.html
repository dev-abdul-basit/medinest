1. Why we're shipping it

The 01-store-listing.md advertises journal + medicine history together as a feature designed around the doctor visit. We currently let users write journal notes but not export them. Adding a "Send to doctor" PDF export delivers the promise the listing makes. It's also the cleanest premium-gated feature we can ship without locking core reminder functionality — premium pays for "send PDF" with no reduction of free-tier ability to track.

2. What changes for the user

  • In Medicine History screen: a new "Export PDF" button (top-right). Premium-gated.
  • In Appointment History screen: same button.
  • Tapping it opens a date-range picker (default: last 30 days), then the user selects which family-member's data and which sections to include (medicines / journal / appointments).
  • Output: A4 PDF, MediNest-branded, includes a generated cover with patient name + date range, then chronological entries.
  • Final action: Share (uses share_plus already in pubspec.yaml) or Save to Files.

8. Manual test plan

Golden path (premium user):

  1. Subscribed user. Open Medicine History.
  2. Tap Export PDF.
  3. Pick last 30 days, self profile, all sections checked.
  4. Tap Generate.
  5. Expected: PDF generated within 5 seconds (for ~100 entries). System share sheet opens. Save to Files. Open in iOS/Android PDF viewer.
  6. Verify content: cover, headers, dates, every dose accounted for.

Edge case 1 — Free user:

  1. Tap Export PDF.
  2. Expected: subscription dialog opens. No PDF generated. CTA routes to ProVersion.

Edge case 2 — Empty range:

  1. Premium user, pick a range with no data (e.g., year 2010).
  2. Expected: PDF still generates with sections showing "No entries in this period." Don't crash.

Edge case 3 — Large data:

  1. Premium user with 365 days of dense data, "Last year".
  2. Expected: PDF generates in <30 seconds, file size <5 MB. If it exceeds, log warning and trim to most recent 365 days.

Edge case 4 — Special characters in medicine name:

  1. Add medicine Vitamin D₃ – 1000mg (Mom's pharmacy) with non-ASCII.
  2. Export.
  3. Expected: renders correctly in PDF. (pdf package uses Helvetica by default — use a UTF-8-safe font; embed assets/fonts/NunitoSans_Regular.ttf for PDF rendering.)

Edge case 5 — Arabic / Hindi data:

  1. Premium user, Arabic locale, medicine names in Arabic.
  2. Export. Expected: RTL text renders correctly. Note: the pdf package's RTL support requires careful font selection — confirm during implementation.

Regression check:

History screens still load and render normally without the export action.
